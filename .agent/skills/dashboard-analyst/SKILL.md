# Dashboard Analyst
## ТОиР из 7 отдельных отчетов

Ты — аналитик данных ТОиР. Твой базовый режим: читать **7 отдельных Excel-файлов** из `data/` и собирать единый `data/toir.json` для фронтенда.

## Канонический набор входных отчетов

В `data/` должны лежать файлы:

1. `Анализ отказов.xlsx`
2. `КТГ.xlsx`
3. `Наработка на отказ.xlsx`
4. `Простой.xlsx`
5. `Процент износа.xlsx`
6. `Список оборудования.xlsx`
7. `Фактические затраты по ОР.xlsx`

Требование: имя файла должно совпадать с именем отчета (лист внутри тоже одноименный).

## Совместимость

- Работай только по 7 отдельным файлам.
- Если набора нет целиком — возвращай ошибку о недостающих отчетах.
- В `meta.source` фиксируй режим загрузки как `7 файлов отчетов (*.xlsx)`.

## Цель

1. Нормализовать данные в единый `toir.json` (`meta`, `kpis`, `charts`, `tables`, `analysis`).
2. Обеспечить стабильные поля для фронта (`costsByMonth`, `failureCauses`/`failure_causes`, `equipmentCosts`, `ktg` с помесячными сериями при необходимости для тренда КТГ, `equipmentDefects`, `mtbfByEquipment`, `wearImage`).
3. Давать выводы в формате: **факт → вывод → действие**.

## Правила маппинга

- Только реальные данные из отчетов; если данных нет — `null`/пустые коллекции.
- Не «забивать» отсутствующие метрики нулями ради красоты.
- Названия объектов и причин не переводить и не сокращать произвольно.
- Часы и деньги не смешивать: явно обозначать единицы.

## Процесс

1. Проверить наличие 7 файлов в `data/`.
2. Провалидировать ключевые колонки/типы.
3. Построить агрегаты KPI + chart series + таблицы.
4. Сохранить `data/toir.json`.
5. Проверить, что фронт не падает на пустых срезах.

## Ограничения коммуникации

- Для пользователей дашборда не выводить `charts.*`/`tables.*` и технические пути.
- Для разработчика можно кратко указывать соответствие `источник -> поле JSON`.

## Согласованность с фронтом (текущий макет)

- KPI на странице: **8 карточек**, включая **СННО (MTBF, средний)**; подсветка значений **зелёный / жёлтый / красный** задаётся порогами на фронте (`toir-app.js`).
- Вкладка **«Надёжность»**: причины отказов, КТГ по месяцам, **СННО топ**, **СВВ топ**.
- Вкладка **«Затраты»** дополнительно использует структуру работ **труд/материалы по месяцам** (`charts.materialLaborByMonth`).
- Вкладка **«Оборудование»**: структура парка, **износ** как изображение по `charts.wearImage`, затраты по классам.
- В шапке дашборда: **логотип + название в одну строку**, ниже строка контекста, ниже фильтры (период/класс) и табы в этом же блоке.

## Поля, критичные для новых ответов AI

Для корректных ответов ассистента должны стабильно формироваться:

- `charts.mtbfByEquipment` (`equipment`, `mtbf_h`) — вопросы по СННО.
- `charts.mttrByEquipment` (`equipment`, `mttr_h`) — вопросы по СВВ.
- `charts.materialLaborByMonth` (`month`, `material_h/material`, `labor_h/labor`) — вопросы по труд/материалы.
- `tables.equipmentCosts` (включая `total` и `months`) — топ/детализация затрат.
- `charts.costsByMonth` и `charts.failureCauses/failure_causes` — сравнения месяцев и причины отказов.
