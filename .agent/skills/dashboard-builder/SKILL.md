# Dashboard Builder — Финальный регламент

## Role

Ты senior frontend-инженер. Собираешь и дорабатываешь дашборд на **Vanilla JS + ApexCharts (CDN)**, данные только из `data/toir.json`, клиентская фильтрация, светлая тема.

### Эталонные файлы

| Назначение | Файл |
|---|---|
| Разметка | `index.html` |
| Стили | `css/toir.css` |
| Логика | `js/toir-app.js` |
| Графики | `js/toir-charts.js` |
| Утилиты Apex/форматирование | `js/toir-utils.js` |
| Данные | `data/toir.json` |
| Логотип (текущий) | `assets/desnol-userpic.png` |

Глобально после загрузки: `window.dashboardData`.

## Финальная структура интерфейса

### 1) Шапка (обязательный текущий вариант)

- Белая карточка (`.header-card`) без маркетинговых слоганов.
- Верхний ряд: слева в одну линию **логотип + заголовок**.
  - Логотип в левом верхнем углу.
  - Заголовок справа от логотипа: `Стратегический дашборд ТОИР`.
- Ниже: строка контекстных чипов
  - `Период`, `Класс`, `Объектов`, `Обновлено`.
- Ниже: единый блок фильтров:
  - `#panelPeriod`, `#panelClass`.
  - Под ними внутри этого же блока — табы: `Сводка / Затраты / Надёжность / Оборудование`.

### 2) Основной макет

- `.layout` = основная зона + правая колонка AI (`.layout-sidebar`).
- Фиксированная рабочая ширина макета допускается через CSS-переменную (`--dashboard-fixed-width`), если это уже принято в проекте.

### 3) KPI

- 8 карточек (2 ряда по 4):
  - `#kpiTotal`, `#kpiTop3`, `#kpiAvgUnit`, `#kpiDown`
  - `#kpiFails`, `#kpiKtg`, `#kpiPerEq`, `#kpiMtbf`
- Для значений KPI использовать классы:
  - `kpi-status-target` (зеленый)
  - `kpi-status-standard` (желтый)
  - `kpi-status-below` (красный)

### 4) Таблицы

- Таблица классов оборудования.
- Таблица «Топ проблемных объектов».
- Колонку/кнопку `Карточка` **не возвращать**.

### 5) AI-блок

- Белый фон панели.
- Заголовок: `AI-ассистент`.
- Под заголовком короткое объяснение блока (не техничное).
- В поле ввода placeholder:
  - `Задайте вопрос, например: "Какой общий объем затрат?"`
- Ответы строго по skill `dashboard-assistant` (факт → вывод → действие, без выдумывания).

## Правила визуального стиля (единые)

### Controls system (обязательно)

Все элементы управления должны выглядеть как одна система:

- `select`, `textarea`, кнопки, табы, control-панели:
  - единые радиусы,
  - единая толщина/тип бордера,
  - согласованные `hover/focus/active`.
- Для **кнопок**:
  - базовое: белый фон + зеленая окантовка + зеленый текст;
  - hover/active: зеленый фон + белый текст.
- Для **панелей/полей ввода-вывода**:
  - рамка стандартного цвета блоков дашборда (`var(--border)`), без случайной зеленой рамки у контейнеров.

### Тексты в UI

- Только понятные бизнес-формулировки на русском.
- Не показывать технические ключи JSON и пути (`charts.*`, `tables.*`) в подзаголовках/подсказках.
- Не использовать фразы вида «уточните в 1С».

## Правила цветов графиков (актуальная версия)

1. Если цвет **не несет смысл легенды** (одна серия, ranking, динамика) — использовать **один зеленый** (`--chart-bar`).
2. Если легенда/категории **действительно важны**:
   - применять единую категориальную палитру как у `Доля затрат по классам` (donut-стиль).
   - тот же подход для multi-series, где цвет разделяет разные сущности.
3. Избегать «радуги» там, где это не добавляет смысла.

## Графики по вкладкам (актуально)

- `Сводка`: `#chartCosts`, `#chartStructure`, `#chartCauses`
- `Затраты`: `#chartCostsTab`, `#chartMaterialLabor`, `#chartTopCostEquip`, `#chartClassCostDonut`
- `Надёжность`: `#chartCausesRel`, `#chartKtgTrend`, `#chartMtbfTop`, `#chartMttrTop`
- `Оборудование`: `#chartStructureEq`, `#chartWearImage`, `#chartClassCostsBar`

Пустые состояния каждого графика: аккуратный текст «Нет данных», без ошибок в консоли.

---

## APEX/JS правила рендера

- Для Apex обязательно:
  - `width: "100%"`
  - `redrawOnParentResize: true`
  - `redrawOnWindowResize: true`
- После переключения таба вызывать `resizeAll()`.
- После `drain()` делать отложенный `resizeAll()` (через `setTimeout`/`requestAnimationFrame`).
- Скрытые панели рендерить безопасно (не допускать «сплющенных» графиков).

---

## KPI-оценка (обязательно)

- Для КТГ и СННО можно использовать фиксированные целевые пороги.
- Для остальных KPI — baseline полного среза и относительные пороги.
- Цвет состояния ставится на `.kpi-card .value`.
- При `NaN/null` не применять классы статуса.

---

## Источник данных `toir.json`

Минимально согласовать с фронтом:

- `meta`: `source`, `period`, `generated` (или эквивалент для «Обновлено»)
- `kpis`: базовые агрегаты
- `charts`: `costsByMonth`, `failureCauses/failure_causes`, `mtbfByEquipment`, `mttrByEquipment`, `wearImage`
- `tables`: данные для таблиц/КТГ/оборудования

## Пошаговая сборка (короткий checklist)

1. Обновить `index.html`: шапка, фильтры, табы внутри фильтр-блока, AI-раздел.
2. Обновить `css/toir.css`: унифицированные контролы, кнопки, панели, типографика.
3. Обновить `js/toir-app.js`: фильтрация, KPI, чипы шапки, табы, AI wiring.
4. Обновить `js/toir-charts.js`: актуальная цветовая политика + `resizeAll`.
5. Проверить 4 вкладки, состояния фильтров, пустые данные, консоль без ошибок.

---

## Definition of done

- Шапка соответствует текущему финальному дизайну.
- Контролы и кнопки приведены к единому стилю.
- Цвета графиков соответствуют правилу: «моно-зеленый по умолчанию, multi-color только при значимой легенде».
- KPI окрашиваются по 3 зонам.
- AI-блок оформлен и текстово соответствует требованиям.
- Нет технического мусора в пользовательских подписях.
