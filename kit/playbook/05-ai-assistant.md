# 05. AI-ассистент — настраиваем чат и агента

Этот шаг опционален. Если вам достаточно KPI+графиков — пропустите до
[07-acceptance.md](07-acceptance.md).

## Два режима

1. **Быстрый чат** (`/api/chat`): вопрос → ответ в формате
   `факт → вывод → действие`. Без инструментов.
2. **Агент** (`/api/agent`): ReAct-цикл с инструментами — `get_kpis`,
   `query_data`, `compute`, `build_table`, `build_chart`, `search_entity`,
   `forecast_metric`. Умеет строить артефакты (таблицы/графики прямо в ответе).

Рекомендация: **включайте оба**. Если облачная модель недоступна, UI
автоматически переключится на быстрый чат; если не хватает ключа —
на локальный fallback.

## Что понадобится

- Выбор провайдера LLM: OpenRouter, OpenAI API, Anthropic, локальный llama.cpp.
  Агент напишет адаптер под любой из них.
- Ключ API провайдера (хранится в `.env`, не в репо).
- Язык ответов (`brand.config.yaml -> assistant.response_language`).
- Формат ответов (`assistant.answer_format`): `fact_conclusion_action` /
  `plain` / `bullets` / `structured`.

## Процедура

1. Заполните секцию `assistant` в `brand.config.yaml`.
2. Убедитесь, что для метрик временных рядов, по которым планируется прогноз,
   стоит `forecastable: true` в `metric-catalog.yaml`.
3. Отправьте агенту промт [prompts/40-setup-agent.md](../prompts/40-setup-agent.md).

Агент по `skills/agent-tools/SKILL.md` сгенерирует:

- сервер-прокси (`/api/chat`, `/api/agent`) на вашем стеке;
- реализацию инструментов поверх `dashboard.json`;
- клиентскую часть (панель чата, рендер артефактов — таблиц и графиков);
- fallback-режим при недоступности модели.

## Правила ответов

Ассистент строго соблюдает `skills/dashboard-assistant/SKILL.md`:

- не выдумывает числа;
- не показывает технические пути/ключи;
- при нехватке данных — формула «Сожалею, но пока не могу ответить…»;
- соблюдает формат ответа из конфига.

## 10 приёмочных вопросов

Подготовьте 10 вопросов разных интентов (см. `skills/dashboard-assistant`):

1. Один простой факт (один KPI).
2. Сравнение двух периодов.
3. Топ-N по метрике.
4. Динамика во времени.
5. Структура по категории.
6. Детализация по конкретному объекту/клиенту.
7. Причина изменения (проверка, что ассистент не додумывает причинность).
8. Прогноз на N периодов (если включён).
9. Рекомендация (проверка ограничений).
10. Вопрос, на который точно нет данных в дашборде (должно вернуться
    «Сожалею…»).

Все 10 ответов проходят — ассистент готов к приёмке.

## Безопасность

- Ключ API не отправляется в браузер. Он живёт только на сервере.
- Если фронт статический и бэкенда нет — ассистент работает только в
  локальном fallback-режиме (без внешних LLM).
- CORS ограничьте списком `ALLOWED_ORIGINS` — только адреса вашего фронта.

## Критерий готовности

- Оба endpoint'а отвечают 200 на корректный запрос.
- Выключение ключа модели не ломает UI — включается fallback.
- 10 приёмочных вопросов проходят.
- В ответах нет технических путей и выдуманных чисел.
