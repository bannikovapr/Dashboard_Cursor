# 04. UI Spec — настраиваем интерфейс

## Цель

Определить, как выглядит дашборд: KPI-карточки, вкладки, графики, таблицы,
фильтры. Всё это — два конфига:

- [templates/metric-catalog.example.yaml](../templates/metric-catalog.example.yaml) — формулы KPI и пороги.
- [templates/ui-layout.example.yaml](../templates/ui-layout.example.yaml) — карта интерфейса.
- [templates/brand.config.example.yaml](../templates/brand.config.example.yaml) — бренд и локаль.

## 4.1 Metric Catalog — что считать

Для каждого KPI задаёте:

- `id` — совпадает с ключом в `dashboard.json -> kpis`.
- `label` — как показать пользователю.
- `unit` — `"USD"`, `"%"`, `"шт"`, `"ч"`, и т.п.
- `formula` — читаемая формула, которую использует агент.
- `thresholds` — зоны `target / standard / below`. Можно использовать
  абсолюты или выражения от `baseline`.
- `format` — стиль и компактность (1.2M vs 1 200 000).

Для временных рядов и многокатегорийных графиков — блок `series`. Там же
пометка `forecastable: true`, если нужен прогноз.

## 4.2 UI Layout — как показать

Блоки:

- `header.chips` — контекстные чипы под заголовком.
- `filters` — селекты и переключатели над KPI.
- `kpi_block` — количество и порядок карточек (responsive-колонки).
- `tabs` — вкладки с набором `charts` и `tables` в каждой.
- `chart_policy` — когда моно-цвет, а когда categorical-палитра.

### Рекомендации

- Вкладок — не больше 4. Если больше — пользователь теряется.
- KPI — 4, 6 или 8. Ровно сетка, без «висящего» 5-го.
- Не кладите на одну вкладку больше 4 графиков — иначе всё будет мелким.
- Для топов и «кто-сколько» — `bar` с одной серией и моно-цветом.
- Для «из чего состоит» — `donut` с categorical-палитрой.
- Для динамики — `line` или `area`.

## 4.3 Brand Config — как это оформить

Важные поля:

- `app.title`, `app.logo` — шапка.
- `palette.*` — все цвета дашборда.
- `typography.font_family` — шрифты (Google Fonts подхватятся автоматически).
- `i18n.locale` и `i18n.currency` — формат чисел, дат, валюты.
- `layout.mode` — `main_only` или `main_plus_sidebar` (с AI-панелью справа).
- `assistant.*` — настройки AI-ассистента (см. шаг 05).

## Генерация интерфейса

Отправьте агенту промт [prompts/30-build-ui.md](../prompts/30-build-ui.md). Он:

1. Прочитает три конфига и `dashboard.json`.
2. Сгенерирует каркас проекта на выбранном стеке (по умолчанию — Vanilla
   HTML/JS/CSS + ApexCharts).
3. Сгенерирует CSS-переменные из `palette`/`typography`.
4. Сгенерирует код KPI-карточек, вкладок, графиков, таблиц и фильтров из
   `ui-layout.yaml`.
5. Подключит биндинги к `dashboard.json`.
6. Запустит локальный сервер и откроет браузер.

Агент действует по `skills/dashboard-builder/SKILL.md`.

## Критерий готовности

- Дашборд открывается в браузере, KPI-числа совпадают с `dashboard.json`.
- Все вкладки переключаются, графики рисуются, таблицы заполнены.
- Адаптив работает на 360/768/1366 как минимум — пройти
  [templates/acceptance-checklist.md §7](../templates/acceptance-checklist.md).
- Замена одного цвета в `brand.config.yaml` меняет UI без правки кода.

## Частые ошибки

- **Слишком пёстрые графики.** Уберите лишние цвета: оставьте `mono_by_default: true`
  и отдельную палитру только для donut/pie.
- **KPI-карточки разного размера.** Держите одну сетку: 4 × 2 или 6 × 2.
- **Логотип тянется.** Задайте `logo.width`/`height` в пикселях и проверьте,
  что картинка — квадратная или с правильным соотношением.
