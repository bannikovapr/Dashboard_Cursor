# 08. Итерация — как жить с дашбордом дальше

## Правило одной точки изменения

Любое изменение должно делаться в ОДНОМ файле, а не в коде:

| Изменение                          | Файл                                         |
|------------------------------------|----------------------------------------------|
| Добавить/убрать KPI                | `metric-catalog.yaml`                        |
| Поменять формулу или пороги KPI    | `metric-catalog.yaml`                        |
| Добавить вкладку или график        | `ui-layout.yaml`                             |
| Поменять цвета, логотип, шрифт     | `brand.config.yaml`                          |
| Поменять язык интерфейса           | `brand.config.yaml -> i18n.locale`           |
| Подключить новый источник          | `source-manifest.yaml`                       |
| Поменять имя колонки в источнике   | `source-manifest.yaml -> mapping`            |
| Включить прогноз для нового ряда   | `metric-catalog.yaml -> series[].forecastable` |
| Поменять формат ответа ассистента  | `brand.config.yaml -> assistant.answer_format` |

Если кажется, что нужна правка кода — это сигнал, что в конфиге не хватает
поля. В 9 из 10 случаев правильный путь: расширить конфиг и попросить агента
перегенерировать этот кусок по промту [prompts/99-fix.md](../prompts/99-fix.md).

## Типовые сценарии

### Добавить новый KPI

1. В `metric-catalog.yaml -> kpis` добавить блок с `id`, `formula`, `thresholds`.
2. В `ui-layout.yaml -> kpi_block.cards` добавить `{ ref: <id> }`.
3. Промт: `Добавь KPI <id> в дашборд по текущему metric-catalog и ui-layout.`.

### Поменять цвет и логотип

1. Отредактировать `brand.config.yaml -> palette` и `app.logo`.
2. Промт: `Обнови стили и шапку по обновлённому brand.config.`.
3. На выходе — CSS-переменные и шапка пересобраны. Код компонентов не трогается.

### Подключить новый источник (напр. добавили ещё одну выгрузку)

1. В `source-manifest.yaml -> sources` добавить блок.
2. Если источник заполняет существующий датасет — убедиться, что поля совпадают.
3. Если новый датасет — добавить в `canonical_datasets`.
4. Промт: `Перестрой dashboard.json по обновлённому source-manifest.`.

### Сменить язык интерфейса

1. `brand.config.yaml -> i18n.locale`.
2. `brand.config.yaml -> assistant.response_language`.
3. Промт: `Перегенерируй подписи и ассистента под новую локаль.`.

### Добавить новую вкладку

1. В `ui-layout.yaml -> tabs` добавить блок с `charts`/`tables`.
2. Если для этих графиков нужны новые серии — добавить в `metric-catalog.yaml -> series`.
3. Промт: `Добавь вкладку <id> в UI по обновлённому ui-layout.`.

## Регулярное обновление данных

1. Заменить файл(ы) в `data/` (или обновить источник в БД/API).
2. Запустить агентский скрипт пересборки (создан на шаге 03).
3. Убедиться, что `meta.generated_at` обновился.
4. Пройти короткую версию acceptance: данные + KPI + графики.

Автоматизация (cron/CI) — отдельный короткий промт в `prompts/99-fix.md`
(раздел «пересборка по расписанию»).

## Версионирование

- Каждое значимое изменение бампайте `meta.version` в `dashboard.json`.
- В git тэгайте версию (`v1.0.0`, `v1.1.0`).
- Храните снимки `dashboard.json` вне репо (каталог `snapshots/` или объектное
  хранилище) — так можно сравнивать периоды.

## Что НЕ делать

- Не писать бизнес-логику в JS/Python коде UI — всё в `metric-catalog.yaml`.
- Не дублировать цвета в двух местах. Источник истины — `brand.config.yaml`.
- Не коммитить данные с персональными сведениями в git. Используйте `.gitignore`
  для папки `data/` и храните её вне репозитория или в защищённом хранилище.

## Definition of Done для итераций

- Любой сотрудник, кто умеет править YAML, может добавить KPI или вкладку.
- Смена бренда — 5 минут правки `brand.config.yaml` + перегенерация UI агентом.
- Журнал изменений ведётся через git-историю конфигов, а не через историю кода.
