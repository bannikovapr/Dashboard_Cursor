# Диагностики ТОиР (вкладка «Диагностика»)

Краткое описание назначения, данных и логики проверок для модуля диагностик дашборда.

## Назначение

На вкладке **«Диагностика»** дашборда показываются **гипотезы** — автоматические проверки по данным ТОиР. Каждая гипотеза отвечает на вопрос: *есть ли в текущем срезе признак определённого риска или перекоса* (концентрация простоев, затрат, проблем классов, повторяемость ремонтов, качество справочника причин и т.д.).

Результат **не заменяет** экспертизу: это ориентиры для разбора данных и приоритизации.

## Источник данных

Все расчёты выполняются **в браузере** и в smoke-тесте из одного агрегата **`data/toir.json`**, собранного из отчётов Excel (см. корневой [README.md](../README.md)).

Используются, в частности:

- блоки **`charts`**, **`tables`** (затраты по объектам, КТГ, отказы, **repairEvents**, причины отказов и др.);
- при необходимости — **`analysis`** (предрасчёты для сводок).

Если в срезе **мало строк** или отсутствуют нужные поля, гипотеза помечается как **«Недостаточно данных»** (`insufficient_data`).

## Срез (фильтры)

Диагностики учитывают те же фильтры, что и основной дашборд:

- **Период** — все 12 месяцев, 1-е или 2-е полугодие 2025;
- **Класс оборудования** — все классы или один выбранный.

Часть правил **намеренно отключена** при фильтре одного класса (например, сравнение классов между собой).

## Статусы гипотезы

| Статус | Смысл |
|--------|--------|
| **Сработала** (`triggered`) | Условия правила в срезе выполнены — стоит разобрать вывод и доказательства. |
| **Не сработала** (`not_triggered`) | Признак в рамках правил не выявлен. |
| **Недостаточно данных** (`insufficient_data`) | Не хватает объёма или полей в данных; вывод ограничен. |

Отдельно задаётся **уверенность** (`high` / `medium` / `low`) — насколько плотно данные поддерживают вывод (размер выборки, тип доказательства).

## Набор правил (идентификаторы)

Логика и пороги **зашиты в коде** модуля [`js/toir-diagnostics.js`](../js/toir-diagnostics.js) (константа `THRESHOLDS`, объекты проверок R* / K*).

- **R1–R18** — правила по простоям, затратам, классам, СВР/СННО, месяцам, причинам отказов, связке затрат и отказов, повторным ремонтам и т.д.
- **K1–K4** — проверки вокруг **КТГ**, **СННО (MTBF)**, **СВР (MTTR)** и пиков **материалов/труда по месяцам**.

Часть правил **помечена как неподдерживаемые** с текущей структурой выгрузки (нет подразделения, дисциплины, отдельных полей для сравнения затрат и потерь от простоя и т.п.) — в интерфейсе они отображаются с соответствующим пояснением.

Под каждой карточкой доступно раскрытие **«Развёрнуто»**: входы, расчёт и пороги (тексты из `DIAG_EXPANDED_EXPLAIN` в том же файле).

## Разработка и регрессия

- Модуль экспортирует функции **`analyzeAll`**, **`summarize`** и константы статусов (используются из [`js/toir-app.js`](../js/toir-app.js) для отрисовки вкладки).
- Проверка контракта: **`npm run smoke:diagnostics`** ([`scripts/smoke-diagnostics.js`](../scripts/smoke-diagnostics.js)) — загружает `data/toir.json`, прогоняет все ожидаемые id (R1–R18, K1–K4), валидирует поля результата.
