# Стратегический дашборд ТОИР

Веб-дашборд по данным ТОИР: KPI, затраты, надежность, структура оборудования.

## Быстрый запуск (для пользователя)

- Дважды кликните `START_DASHBOARD.cmd` в корне проекта.
- Скрипт автоматически:
  - обновит `data/toir.json` из Excel через `scripts/analyze_toir.py`;
  - поднимет локальный API-прокси OpenRouter (`http://localhost:8787`);
  - откроет браузер с дашбордом;
  - запустит локальный сервер.

## Альтернативно через PowerShell

```powershell
.\scripts\start-dashboard.ps1
```

Опции:

- `-NoRefresh` — запуск без пересчета `toir.json`;
- `-Port 5173` — указать порт.

Пример:

```powershell
.\scripts\start-dashboard.ps1 -Port 5180 -NoRefresh
```

## Настройка OpenRouter (обязательна для облачного режима AI)

1. Установите Node.js (если еще не установлен).
2. Выполните в корне проекта:

```powershell
npm install
copy .env.example .env
```

3. Откройте `.env` и вставьте ключ в строку:

```env
OPENROUTER_API_KEY=your_openrouter_key_here
```

4. Запустите дашборд через `START_DASHBOARD.cmd` или `.\scripts\start-dashboard.ps1`.

## Структура проекта

- `data/` — исходный Excel и итоговый `toir.json`
- `scripts/` — анализ данных и запуск локального сервера
- `css/`, `js/`, `index.html` — фронтенд дашборда
- `assets/` — брендинг

Актуальный фронтенд использует:
- `css/toir.css`
- `js/toir-utils.js`
- `js/toir-charts.js`
- `js/toir-app.js`

## AI-ассистент

- Блок AI-ассистента работает в двух режимах:
  - **облачная модель** через серверный endpoint `POST /api/chat`;
  - **локальный fallback** (`aiAnswer`) при отсутствии ключа или ошибке запроса к модели.
- API-ключ OpenRouter хранится только на сервере (в `.env`) и не передается в браузер.
- Источник контекста для ответов: `window.dashboardData` (данные из `data/toir.json`).
- Контекст для LLM формируется по гибридной схеме:
  - `broad` (общий вопрос) -> базовый обзор + целевой блок;
  - `narrow` (узкий вопрос) -> целевой блок по интенту;
  - `mixed` -> обзор + интентный блок с более строгим лимитом.
- Если первый ответ модели сигнализирует о нехватке данных, backend делает 1 ретрай с расширенным контекстом (`contextExpanded`).

### Примеры маршрутизации контекста

- Broad: `Сделай общий анализ дашборда`, `Что важного по всему ТОИР?`
- Narrow: `Топ-3 причины отказов`, `Сравни затраты за март и апрель`
- Mixed: `Дай общий обзор и отдельно по надежности`

## Источники данных (новый стандарт)

Предпочтительный режим: 7 отдельных файлов в `data/`:

- `Анализ отказов.xlsx`
- `КТГ.xlsx`
- `Наработка на отказ.xlsx`
- `Простой.xlsx`
- `Процент износа.xlsx`
- `Список оборудования.xlsx`
- `Фактические затраты по ОР.xlsx`

Скрипт `scripts/analyze_toir.py` объединяет их в единый `data/toir.json`.

Совместимость: если полного набора нет, используется `data/Cursor_test2.xlsx` (legacy).
